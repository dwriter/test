# Устройство приложения

Все модули — обычный JavaScript без сборочного runtime, внешних API и зависимостей. Один namespace `DND`; порядок script в index.html задаёт зависимости. Данные SRD загружаются синхронно из включённого файла, поэтому нет сетевой гонки и режима «данные ещё не скачаны».

| Файл | Ответственность |
|---|---|
| dice.js | криптографический генератор, ограниченный парсер формул, d20, режимы, крит |
| srd-data.js / data/*.json | полный снимок структурированного SRD 2014 |
| content.js | объединение SRD и пакетов, поиск, переводы меток, варианты снаряжения |
| effects.js | активность, длительность, прибавления, задания значений, источники advantage/disadvantage |
| rules.js | производные показатели, владения, AC, HP, скорость, ячейки, ресурсы |
| character.js | создание, модели предметов, повышение уровня, валидация |
| actions.js | изменение HP, атаки, заклинания, состояние, отдых; Session и History логически выделены функциями |
| storage.js | IndexedDB, транзакции, откат, снимки, импорт/экспорт и миграция v3 |
| app.js | экраны, формы и пользовательские команды; использует функции движка |
| service-worker.js | локальный кэш приложения и обновление по команде |

## Character State, schemaVersion 4

- `id`, `name`, `playerName`, `alignment`, `race`, `subrace`, `background`, `mode`, `portrait`, `notes`.
- `abilities` — базовые характеристики; `racialBonus` — выбираемые расовые бонусы; `asi` — повышения. Автоматические расовые бонусы берутся из Content, а не записываются второй раз.
- `classes[]` — `{id,level,subclass,hpRolls[],hdUsed}`. Каждый элемент hpRolls хранит результат Hit Die без CON; изменение CON пересчитывает все уровни.
- `skills` — ранги 0/1/2; `proficiencies` — дополнительные владения; исходные классовые владения вычисляются из первого класса и правил мультикласса.
- `hp`, `tempHP`, `death`, `conditions[]`, `exhaustion`, `concentration`, `pendingConcentration[]`.
- `inventory[]` — копии карточек с uid, quantity, weight на единицу, equipped, attuned, effects; `coins` — пять номиналов.
- `spells[classId]` — known/prepared; `slotsUsed[9]`, `pactUsed`; `resourceUsed[id]`, `customResources[]`.
- `effects[]`, `feats[]`, `featureChoices[]`, `choices`, `favorites[]`.
- `session` — игровое время в секундах, номер раунда, отметки действия/бонуса/реакции, время последнего результата длительного отдыха.
- `history[]` — время, заголовок, расчёт и структурированный результат броска.

## Storage State

`{schemaVersion:4, characters[], active, packs[], theme, undo[], backups[], savedAt}`.

Каждая команда изменения выполняется через `Storage.change`: снимается копия, применяется действие, результат записывается транзакцией IndexedDB. При исключении состояние возвращается к исходному. Последние 30 снимков сохраняются вместе с состоянием и работают после перезапуска. Три ручные резервные копии не включают вложенные Undo/backup, чтобы избежать рекурсивного роста.

Экспорт — JSON без исполняемого кода. Импорт сначала разбирает весь файл и проверяет персонажей, затем выполняет одну транзакцию; конфликт пакета прерывает импорт. Запрещены ключи прототипов. Строки контента экранируются перед выводом в HTML. В портретах разрешены только встроенные PNG/JPEG/WebP.

## Расчёты

Модификатор характеристики: floor((score−10)/2). Мастерство: 2+floor((totalLevel−1)/4).

Навыки: модификатор + PB × ранг + числовые эффекты; Bard 2 добавляет половину PB только при отсутствии владения. Пассивный навык: 10 + итоговый бонус ±5 от advantage/disadvantage.

AC использует одну применимую формулу брони/защиты без доспехов, затем щит и добавочные эффекты. Отрицательный DEX остаётся отрицательным в средней броне. Универсальные эффекты `set` задают значение показателя, а не альтернативную формулу с приоритетом «только если выше».

HP складываются по всем сохранённым Hit Dice с текущим CON; минимум 1 за уровень; применяются некоторые постоянные особенности (Hill Dwarf, Draconic) и истощение 2014.

Суммарные ячейки вычисляются по таблице Wizard для смешанного spellcasting с округлением уровней каждого половинного класса вниз. Один половинный класс пользуется собственной таблицей. Warlock Pact Magic хранится отдельно. Custom-классы с нестандартной прогрессией требуют расширения Rules; данные класса сами по себе не исполняют произвольную механику.

Damage: иммунитет → сопротивление (однократно, вниз) → уязвимость → временные HP → обычные HP → смерть/концентрация. DC концентрации основан на полученном уроне до поглощения временными HP, после сопротивления.

Dice использует ограниченную грамматику, не eval. Крит увеличивает количество кубиков, сохраняя постоянные слагаемые. d20 хранит оба результата и выбранный natural. Натуральные 1 и 20 не дают автоматического исхода обычным навыкам и спасброскам.

## Экраны

На мобильном устройстве всегда доступна нижняя панель: Игра / Лист / Магия / Вещи / Правила / Ещё.

«Игра»: имя, отдых и следующий ход; HP; AC/инициатива/скорость/PB; состояния и концентрация; Quick Bar; атаки и ресурсы; общие действия; журнал.

«Лист»: характеристики, объяснение расчётов, навыки, спасброски, особенности, эффекты и заметки.

Формы открываются в модальных панелях, на узком экране — у нижнего края. Любой изменяющий ввод имеет явную кнопку применения. Закрытие неподтверждённой формы отменяет только её черновик, а не сохранённого персонажа.

## Расширение

Для нового автоматического умения добавляйте чистый расчёт в Rules, действие в Actions и тест со случаем границы. UI должен только собрать выбор игрока и показать результат. Не извлекайте механику из произвольного текста автоматически.
